# LurkNotes: синхронизация с сайтом — карта

**Статус:** карта закрыта. Все тикеты решены; следующий шаг — написать
спеку синхронизации по решениям ниже.

Цель — спека, а не работающая фича (решение 1.1). Реализация пойдёт отдельным
заходом после написания спеки.

## Destination

Утверждённая спека двусторонней синхронизации заметок между десктопным
приложением (GitHub `hoter/lurknotes`) и сайтом (GitLab `hoter/lurknotes`):
модель данных и протокол, правила конфликтов и удалений, минимальный веб-UI,
настройка в приложении и аутентификация. Спека должна быть самодостаточной:
по ней можно написать оба конца, не переспрашивая.

- Контракт API — OpenAPI в репозитории сервера как источник правды (2.2).
  Клиент проверяет свои модели против него в CI.

- Skills: решения — `grilling` + `domain-modeling`; факты — `research`.

## Decisions so far

- [Grilling: цель и границы](issues/01-grilling-scope.md): цель — спека; сервер проектируем с нуля, веб-UI входит в объём; контракт — OpenAPI в репозитории сервера; карта покрывает обе стороны, тикеты реализации живут там, где код.
- [Grilling: модель данных и порядок](issues/02-grilling-data-model.md): синхронизируем `id`, `text`, `created`, `updated`, `position`; идентичность — UUID4 на клиенте; порядок — число `position` на заметке, формат `notes.json` меняется.
- [Grilling: конфликты, удаление и транспорт](issues/03-grilling-conflict-transport.md): «последняя запись побеждает» по серверному времени (`server_updated_at`); удаление через надгробия на 30 дней; push при сохранении с очередью на диске + pull при старте. Research 06 добавил: нужен plug `network`, блокирующий HTTP — в фоновом потоке, очередь на `queue.json`, второй `Retrier`.
- [Grilling: вход, веб-UI и хранение секретов](issues/04-grilling-auth-surfaces.md): email + пароль (Fortify) и Sanctum-токен устройства; на сайте список заметок и открытие одной; синхронизация — явный тумблер с паузой, по умолчанию выключена; настройки в `sync.json`; токен — файл 0600, без `libsecret`.
- [Task: продуктовая граница для синхронизации](issues/08-task-spec-v11.md): спека v1 правится ссылкой на эту карту (вместо «синхронизация вне всёго»), `notes.json` получает `position` и `server_updated_at` с миграцией при чтении, критерий «нет сети» остаётся контрактом выключенного тумблера; в глоссарий добавлены Sync, Vault, Tombstone.
- [Research: схема хранения и синхронизации в Laravel](issues/05-research-laravel-storage.md): Sanctum + Fortify + Scramble — единственное, чего не хватает из коробки; `unique(['user_id','client_id'])`, UUID строкой в нижнем регистре, индекс `(user_id, server_updated_at)`; **`delete()` не бампает `server_updated_at`** — удаление ставит его само; ретенция — `Schedule::command()->daily()` в `routes/console.php`.
- [Research: HTTP, офлайн-очередь и таймеры в клиенте](issues/06-research-client-http-queue.md): `http.client` из core24, ноль новых зависимостей; `apps.lurknotes.plugs: [network]` — единственная правка `snapcraft.yaml`; `probe_network` в приёмке остаётся валидной для выключенной синхронизации, для включённой — локальный мок-сервер.
- [Prototype: настройка синхронизации в интерфейсе колоды](issues/09-prototype-settings-ui.md): статус — строка-тумблер в веере и цветная точка в шапке (D), настройка — страница Sync в панели по `Set up` и `Ctrl+,` (C); в палитру добавляются `#7bb489` и `#c98a6b`; выключенное состояние показывает подсказку; онбординг упоминает синхронизацию. Мокапы — `prototype/mockups/`, генератор — `scripts/sync_settings_mockups.py`.

## Not yet specified

Маршрут пройден; остались вопросы, которые решает **сама спека**, а не
следующий тикет карты. Они записаны здесь, чтобы не потерялись:

- **Публикация OpenAPI**: Scramble по умолчанию отдаёт `/docs/api.json`
  только в `local` (гейт `RestrictedDocsAccess`). Выбираем: коммитить
  экспортированный `api.json` в репозиторий или открывать URL публично —
  влияет на то, как клиент проверяет модели в CI.
- **Как отдавать надгробия в pull**: они должны приходить через
  `withTrashed()`; надо записать форму ответа, чтобы клиент отличал
  «удалено» от «отсутствует».
- **Удаление снапа**: токен и настройки уходят вместе с данными —
  предупреждать ли и как.
- **Поведение страницы Sync в панели**: как `Esc` и `»` возвращают к
  вееру, что делает peek, пока она открыта, и что показывает
  `Last sync` без сети.
- **Спека синхронизации как документ**: `.scratch/sync/spec.md` отдельно
  или раздел в `edge-notes/spec.md`.

## Out of scope

- **Плата, подписка, квоты.** Синхронизация бесплатна и безлимитна для
  личного аккаунта; монетизация — отдельная карта.
- **Общие заметки, коллаборация, шаринг.** Заметка принадлежит одному
  пользователю.
- **Слияние правок одной заметки по строкам** (CRDT, git-подобный merge).
  По решению 3.1 побеждает последняя запись.
- **Хостинг, домен, TLS, почта.** Допущение: сайт публичный, TLS и почта
  будут; провайдер выбирается в реализации.
- **Мобильные приложения и веб-клиент для них.**
- **Миграция существующих заметок между устройствами** (ручной перенос
  `notes.json`) — уже описана в спецификации данных.
