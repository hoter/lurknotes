# 08: Надёжность хранения

**What to build:** Испорченный файл не уносит заметки: приложение восстанавливается из бэкапа, не перезаписывает незнакомую версию и честно говорит, если записать не удалось.

**Blocked by:** 02

**Triage:** ready-for-agent
**Status:** resolved

- [x] Битый JSON: загружается `notes.bak.json`, битый файл сохраняется как `notes.corrupt-<ts>.json`, пользователь видит ошибку.
- [x] Битый бэкап: пустой список, ошибка, исходный файл не перезаписывается до действия пользователя.
- [x] `version` больше поддерживаемой: режим только чтения, ошибка, никаких записей.
- [x] Нет прав на запись: приложение работает в памяти, показывает «Save failed» и повторяет запись.
- [x] Тесты покрывают каждую ветку восстановления.

## Answer

Реализовано: битый main + валидный backup → восстановление, `notes.corrupt-<ts>.json`, видимая ошибка, persist и корректный restart (маркер `notes.recovering` закрывает crash-window); битый main + битый backup → пустая колода, ошибка, запись заблокирована до `Continue`, первый save после него сохраняет оригинал; future version → read-only без записей; недоступный каталог → работа в памяти, `Save failed`, bounded retry только пока dirty. Тесты покрывают каждую ветку; evidence: `tests/test_store.py`, `tests/test_retry.py`, `scripts/smoke_storage.py`.
